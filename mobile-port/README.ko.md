# ShotTracer Android 및 iPhone 전환 계획

작성일: 2026-11-03. 상태: 1차 개발용 시제품 구현. Android·iPhone 앱 소스와 공통 자동 추적 코어를 이 폴더에 추가했다. 스토어 출시 및 실기기 검증은 아직 완료하지 않았다.

## 1. 목표와 전제

기존 골프 영상 편집기를 Android와 iPhone에서 사용할 수 있도록 만든다. `../AGENTS.md`, `../docs/ARCHITECTURE.md`, README 두 언어판 및 실제 소스를 기준으로 검토했다. 사용자가 확정한 첫 버전 요구는 **휴대폰 단독·오프라인 사용과 자동 공 추적**이다. 첫 구현은 SwiftUI(iPhone)·Kotlin(Android)과 공통 C++ 코어를 사용한다. 현재 개발 환경에서 네이티브 영상 API를 직접 검증하기 위한 선택이며, 기기 검증 후 조정할 수 있다. 자동 추적은 기존 앱처럼 사용자가 시작 공 위치를 지정한 뒤 분석하는 방식으로 계획하며, 시작 위치까지 자동 탐지하는 기능은 별도 요구로 구분한다.

현재 Python 3.13 + FastAPI + pywebview/PyInstaller 구조를 APK 또는 iOS 앱으로 단순 변환할 수는 없다. 특히 Python MediaPipe/OpenCV 의존성, 외부 ffmpeg 프로세스, 파일 경로 접근은 모바일용 대체 구현이 필요하다. Python 자체의 모바일 실행 가능성과 이 프로젝트 전체의 모바일 호환성은 별개다.

모바일 소스·설계·검증 도구는 이 폴더 안에 추가한다. 기존 앱 소스, 프로젝트 데이터, 워터마크 동작은 변경하지 않는다. 작업 시작 시 루트 README 두 파일은 수정 상태였고 `AGENTS.md`, `docs/`는 미추적 상태였다. 해당 기존 작업은 유지했다.

## 2. 구현 방식 비교

| 방식 | 기존 코드 활용 | 휴대폰 단독 사용 | 판단 |
| --- | --- | --- | --- |
| Flutter 화면 + 공통 C++ 처리 엔진 + Swift/Kotlin 연동 | 알고리즘·프로젝트 형식·테스트 기준 재사용, Python/JS 구현은 이식 | 가능하도록 설계 | 공통 화면이 필요할 때 검토할 대안 |
| Swift iOS + Kotlin Android 개별 앱 | 알고리즘을 공통 엔진으로 공유 가능 | 가능하도록 설계 | 첫 구현에 선택. 플랫폼별 화면 유지보수 필요 |
| WebView/PWA로 현재 화면 포장 | HTML/JS 일부 활용 | 현재 백엔드 그대로는 불가 | 터치 화면과 분석·내보내기 엔진을 별도로 해결해야 함 |
| 휴대폰 화면 + PC 또는 클라우드 처리 | Python 엔진 활용도가 높음 | 불가 | 현재 로컬 전용 원칙과 달라 별도 요구 확인 필요 |

Flutter는 네이티브 코드 호출을 지원하지만 영상 분석 엔진을 제공하지는 않는다. 제안 구조는 Flutter → 플랫폼 채널/FFI → 공통 처리 엔진 및 OS 영상 어댑터다. 큰 영상 프레임을 채널로 반복 복사하지 않고 네이티브 버퍼/텍스처를 사용하도록 검증한다. [Flutter 공식 문서](https://docs.flutter.dev/platform-integration/platform-channels)

휴대폰의 `127.0.0.1`은 휴대폰 자신이다. 현재 PC 서버에 자동으로 연결되지 않으며, PC 서버 주소만 바꿔 공개하는 방법은 이번 범위에 포함하지 않는다.

| `web/i18n.js` | en/ko 키를 유지하고 모바일 번역 리소스와 대응표 작성. 기존 웹 UI 변경 시 모든 문자열은 계속 이 파일 사용 |
| `desktop.py`, `packaging/` | 모바일 빌드로 재사용하지 않음. Android/iOS 별도 서명·빌드·테스트 절차 필요 |
| `watermark.py` | 기본 표시와 salted scrypt 비밀번호 검증 유지. 해제 흐름과 저장 정책을 기기별로 검증 |

MediaPipe는 Android/iOS용 Pose Landmarker와 선택적 인물 마스크를 제공한다. 그러나 현재 Python 파이프라인과 동일한 속도·정확도는 실기기로 검증해야 한다. [Android 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/android), [iOS 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/ios)

Android Transformer는 하드웨어 영상 처리와 사용자 정의 효과를 지원한다. iOS는 AVFoundation을 입출력 후보로 검증한다. 이것만으로 기존 tracer 렌더링이 구현되는 것은 아니며, 공통 합성 엔진을 별도로 연결해야 한다. [Android 문서](https://developer.android.com/media/media3/transformer), [Apple 문서](https://developer.apple.com/av-foundation/)

## 4. 모바일에서 특히 검증할 사항

- **시간과 회전:** 휴대폰 가변 프레임률(VFR), 세로 영상 회전 메타데이터, 미러링을 처리한다. 원본 타임스탬프와 기존 프레임 인덱스의 대응을 정의해야 한다. 구형 프로젝트의 좌표 의미는 바꾸지 않는다.
- **좌표:** video px → analysis px → reference → output 변환을 보존한다. 터치 좌표에는 화면 배율·레터박스·핀치·회전 역변환이 필요하다.
- **메모리:** 현재 `video.read_analysis_frames`는 분석 구간의 회색 프레임을 리스트로 유지한다. 예를 들어 960×540×960프레임×1바이트는 약 475 MiB이며, 부가 버퍼는 제외한 값이다. 스트리밍/구간 처리로 바꿀 때 카메라 기준 프레임과 3프레임 차분 문맥을 유지해야 한다. 세로 영상은 가로 폭만 제한하면 높이가 커지므로 최대 변 또는 총 픽셀 수도 제한한다.
- **동일한 결과:** 모바일 미리보기와 내보내기는 같은 장면·경로·글꼴·합성 규칙을 사용한다. Flutter 캔버스에만 tracer를 그리는 구현은 허용하지 않는다. GPU/코덱 차이는 허용 오차를 정해 비교한다.
- **저장소:** 갤러리 자산은 데스크톱 절대경로와 다르다. 첫 버전은 선택 영상을 앱 저장소에 복사하는 안으로 시작하고 용량·정리 정책을 표시한다. iCloud 등 원격 원본은 로컬 확보 후 오프라인 편집한다. Android Photo Picker는 선택 영상 접근에 활용한다. [공식 문서](https://developer.android.com/training/data-storage/shared/photo-picker)
- **중단과 복구:** 앱 전환·화면 잠금·OS 종료를 가정한다. 작업 상태를 디스크에 기록하고 원자적 저장·취소·재시작을 구현한다. 백그라운드에서 계속 실행된다고 가정하지 않는다.
- **출력:** 첫 검증은 SDR H.264 MP4와 일반 속도 원본 오디오를 대상으로 한다. HEVC/HDR·고속 촬영은 별도 확인한다. 슬로모션 오디오 제외라는 현재 제한은 초기에는 유지하고 화면과 설명에 알린다.
- **제품 원칙:** 영상 업로드·텔레메트리·새 네트워크 호출 없이 처리한다. 거리·속도는 현재처럼 사용자가 입력하며 단일 영상에서 실제 측정값이라고 표시하지 않는다.

## 5. 필요한 장비와 준비사항

사용자 요청은 **iOS 26.6.2 이상 지원**으로 해석한다. 이는 최소 OS 버전 요구이며 기기 모델명이 아니다. 실제 SDK·deployment target 설정 가능 여부와 해당 OS를 사용하는 기기 성능은 구현 단계에서 검증한다. Android 최소 지원 버전은 사용자 지정에 따라 **Android 14 이상**으로 계획한다. 아직 두 플랫폼의 앱 호환성을 검증하지 않았다. 최소 지원 OS와 스토어 제출용 target SDK는 별도로 관리한다.

| 항목 | 현재 확인 / 필요한 준비 |
| --- | --- |
| iOS 개발 Mac | 현재 Mac에서 Xcode 27.2 및 개발 경로 확인. 실제 iOS 빌드·서명·연결 기기 검증은 아직 하지 않음 |
| Android 개발 환경 | Android Studio, Android SDK, 호환 JDK 필요. `adb`가 PATH에서 발견되지 않았으며 전체 설치 여부는 미확인 |
| 공통 UI 도구 | Flutter 후보. `flutter`가 PATH에서 발견되지 않았으며 아직 설치하지 않음 |
| 실제 기기 | iPhone과 Android 각 1대 이상. 모델명·OS 버전·여유 공간 확인 필요 |
| 검증 영상 | 공유 가능한 드라이버/칩/퍼트, 세로·가로, 30/60fps 및 고속 촬영 표본. 영상은 Git에 커밋하지 않음 |
| 배포 준비 | 앱 이름·아이콘·지원 연락처·개인정보 설명·서명 키 보관 정책. 계정은 소유자가 관리 |

App Store/TestFlight 배포에는 일반적으로 Apple Developer Program이 필요하며 공식 안내는 연 US$99다. 본인 기기 Xcode 테스트는 무료 계정으로 시작할 수 있다. [Apple 안내](https://developer.apple.com/programs/)

Google Play 등록비는 공식 안내상 US$25 일회성이다. 배포 시 계정 유형별 확인·테스트 요건과 제출 시점의 SDK 요건을 다시 확인한다. Android 로컬 기기 테스트를 시작하는 데 Play 등록은 필요하지 않다. [Google 안내](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)

비용은 2026-11-03 확인 기준이며 지역·세금 등에 따라 달라질 수 있다. 개발 기간과 총비용은 기기 성능 검증 및 기능 범위 확정 후 산정한다.

**확정된 배포 목표는 Apple App Store와 Google Play 공개 출시다.** 개인용 설치만으로 완료 처리하지 않는다. 다음을 출시 준비 범위에 포함한다.

## 6. 단계별 구현과 완료 기준

1. **기술 검증:** 두 기기에서 영상 선택 → 한 프레임 해독 → 공통 엔진 tracer 합성 → 짧은 MP4 저장. 회전·소리·한글·워터마크, 미리보기와 출력 일치를 확인한다. 시간·최대 메모리·발열을 측정하고 iOS 26.6.2 이상이라는 요청 범위에서 도구·기기 호환성을 검증한다. Android 14 이상에서도 같은 항목을 검증하고 기술 선택을 확정한다.
2. **내부 편집 검증:** 영상 선택, 타격 프레임, 수동 시작/정점/착지, 궤적 속도, 스타일, 실행 취소/다시 실행, 저장/불러오기, en/ko, 워터마크 잠금과 영상 저장. 자동 분석 연결을 위한 개발 중간 단계이며 첫 출시 완료로 간주하지 않는다.
3. **자동 추적:** 카메라 보정 → 공 후보/발사/비행 모델 → 인물 마스크/손목 → 스윙/퍼트 순으로 이식하고 기기 표본을 비교한다. 편집이 재분석을 유발하지 않는지 확인한다.
4. **기능 확대와 배포:** 최대 4샷, 팝업·로고·도형, 슬로모션·일괄 작업, 호환 프로젝트 이전 및 중단 복구. 서명한 기기 빌드와 사용자 테스트 후 스토어 제출을 준비한다.

첫 출시는 두 플랫폼에서 PC·클라우드 없이 영상 선택 → 시작 공 지정 → 자동 공 추적 → 궤적 보정 → 미리보기 → 영상 저장이 완료되어야 한다. 수동 편집만 가능한 앱은 출시 요구를 충족하지 않는다. 추적이 끊긴 구간의 예측과 착지 보정은 현재 제품 방식대로 구분해 표시한다. 자동 추적의 처리 시간·메모리·성공 기준은 대표 영상과 대상 기기를 확보한 뒤 측정해 정한다. 사용자가 이후 양쪽 플랫폼의 인물 가림·자동 클럽/손목·퍼트 추적을 요청했으며 구현 범위는 9절에 정리했다.

## 7. 코드와 변경 이력 저장 방침

앱은 `app/android/`와 `app/ios/`, 공통 엔진은 `core/`, 합성·수치 테스트는 `tests/`, 개발 도구는 `tools/`에 저장한다. 플랫폼 앱은 같은 C ABI를 호출한다. 첫 구현에서 데스크톱 Python 코드나 프로젝트 데이터를 수정하지 않았다.

앱 설치 파일·서명 인증서·비밀번호·실제 영상·빌드 산출물은 커밋하지 않는다. 데스크톱 공통 코드 변경이 필요해지면 원인을 기록하고 별도 변경으로 진행한다. 변경은 `codex/mobile-port-plan` 브랜치에서 개발하고 검증 후 초안 PR로 검토한다. 기존 루트 README 및 문서의 사용자 수정은 모바일 커밋에 포함하지 않는다.

## 8. 사용자에게 필요한 결정

- 확정: PC 없이 휴대폰 단독·오프라인 사용, 첫 출시부터 자동 공 추적 포함.
- 이후 확정: Android와 iPhone 모두 인물 가림·자동 클럽/손목 경로·전용 퍼트 추적 포함.
- 지원 목표: iOS 26.6.2 이상, Android 14 이상. 추가 확인: 실제 테스트 기기 모델과 설치 OS, 대표 영상의 해상도·fps·길이.
- 확정: App Store·Google Play 공개 배포, Google Play 개발자 계정 보유. 추가 확인: Google 계정 유형·생성일·확인 및 프로덕션 액세스 상태, Apple Developer Program 미가입에 따른 가입 준비, 무료/유료 판매 방식.
- 확정: 요청한 편집·자동 분석 기능을 두 플랫폼 모두에 적용.

Android와 iPhone 모두 위 요구를 목표로 한다. 수동 편집은 내부 검증 및 자동 추적 실패 시 보정 수단이다. 계정 비밀번호나 서명 키를 채팅에 보낼 필요는 없다.


## 9. 현재 구현과 개발 방법

### 구현한 범위

새 로고 원본: [ShotTracer 로고 v1](assets/brand/shottracer-logo-v1.png). 생성 프롬프트와 적용 범위는 [제작 기록](assets/brand/DESIGN.md)에 보관했다.

- 청록색 실행·선택 버튼, 둥근 영상 카드, 전면 비행 샷/퍼트 전환, iPhone 네이티브 Glass 버튼으로 어두운 편집 UI를 개편했다. 확대된 영상 작업 영역, 접근성 이름이 있는 아이콘 버튼, 화면 확대/복귀, 원본 프레임 단위 앞뒤 이동과 프레임 번호 표시. 선택한 샷의 타임라인 위에 노란 시작 공·초록 착지 깃발을, 아래에는 원본 시각·프레임 버튼을 표시한다. 마커를 드래그해 시간을 직접 수정할 수 있다(아래 설명). 마커나 버튼을 누르면 가장 가까운 원본 프레임으로 이동하고 영상 위 시작·착지 핸들에 이름이 표시된다. 자동 예측 착지는 ‘예상’, 영상 범위를 넘는 시각은 ‘영상 밖’으로 구분하고 이동을 막는다. 이벤트 시각은 궤적 그리기 속도·출력 슬로모션과 무관하게 시작 시각+비행시간 기준이다. Android 아이콘을 길게 누르면 설명을 볼 수 있다. 가로·세로 영상은 잘라내지 않고 화면에 맞춘다.
- 영상당 최대 4샷 추가·선택·삭제, 시작 공과 프레임 선택, 선택 샷 자동 분석, 시작점·정점·착지점 드래그, 현재 프레임을 착지 시각으로 지정, 비행시간·정점 도달시간·궤적 속도 조절. 실행 취소/다시 실행은 최대 50개 편집 상태를 보관하며 편집 시 재분석하지 않는다.
- 공통 C++ 원근 비행 모델 피팅, 착지 재피팅, 정점 보정을 데스크톱 Python과 수치 비교했다. 자동 관측점·`baseModel`은 편집과 별도 보관한다. 관측 소실 후 비행은 예측이며 실제 착지점을 지정하면 보정할 수 있다.
- 자동 인물 가림·손목 중점·클럽 헤드 경로와 전용 템플릿 매칭 퍼트 추적. 자세한 기기 내 분석 방식은 아래에 설명한다.
- 5가지 궤적 프리셋(classic/TV/neon/comet/minimal), 샷 색상, 두께·발광·잔상, 공 머리·착지 마커, 수동 시작/정점/착지 곡선, 끝점 이동이 가능한 원·선, 프레임별 수동 스윙 포인트.
- 8종 팝업의 위치·표시 시간, 로컬 로고 선택·크기·투명도·모서리, 타격 전후 무음 슬로모션, 프로젝트 저장/다시 열기, 초기화, 순차 일괄 내보내기. 거리·속도는 영상 측정값이 아닌 사용자 입력값이다.
- 정상 속도 출력은 네이티브 미디어 API로 원본 오디오를 포함한다. 슬로모션은 무음이다. 각 플랫폼의 미리보기·출력은 같은 `EditorRenderer`를 사용하여 모든 샷·도형·팝업·로고·기본 워터마크를 합성한다. 선택 핸들은 조작용이며 출력에 포함하지 않는다.
- 앱 내부 영상 복사 및 `mobile-project.json` 편집 상태 원자적 저장. PC·클라우드 처리나 실행 중 네트워크 요청이 없다. 모바일 프로젝트는 새 버전 1 형식이며 데스크톱 프로젝트 폴더 가져오기는 지원하지 않는다. 앱 전용 로고 경로는 기기 간 이동할 수 없다.
- iPhone: SwiftUI, Photos/Files 영상 선택, AVFoundation 출력, 앱 내부 완성본 재생·공유. 전체 사진 보관함 접근 권한 없이 선택 파일을 복사한다. iCloud 전용 원본은 시스템 다운로드가 끝나야 오프라인 편집할 수 있다.
- Android: Kotlin, 시스템 영상 선택기, JNI, 정상 속도 Media3 출력, 슬로모션 MediaCodec 출력, 앱 내부 완성본 리뷰와 MediaStore 사진 앨범 자동 저장. INTERNET이나 광범위 갤러리 권한이 없다.
- 양쪽 라이브 카메라는 촬영 중 관측 궤적을 표시하고 합성 영상을 저장하며 완성본 리뷰를 제공한다. 카메라·선택적 마이크 권한은 라이브 화면에서만 요청한다. 상세 제한은 아래에 설명한다.
- en/ko UI는 Android 리소스와 iOS 번역 문자열에서 관리한다. 데스크톱 웹 번역 체계는 유지한다. 워터마크는 계속 표시하며 모바일 비밀번호 해제 UI는 미구현이다. 데스크톱 scrypt 검증은 보존한다.

### 검증과 빌드

저장소 루트에서 전체 테스트:

```bash
uv run pytest
```

기존 50개와 모바일 코어 18개를 합친 68개가 통과했다. 코어 테스트에는 C++17 컴파일러가 필요하며, 없으면 해당 테스트는 skip된다. 데스크톱 피팅·재피팅·정점 계산 일치, 수동 곡선의 정확한 끝점·속도, 합성 공 추적, 정지 공, 관측 소실, 카메라 이동, 가변 시간 간격과 렌더링 시점을 확인한다.

Xcode 프로젝트는 저장소에 포함되어 있으며 다음 명령으로 재생성할 수 있다.

```bash
python3 mobile-port/tools/generate_ios_project.py
xcodebuild -project mobile-port/app/ios/ShotTracer.xcodeproj \
  -scheme ShotTracer -configuration Debug -sdk iphoneos \
  -destination generic/platform=iOS \
  -derivedDataPath /tmp/shottracer-mobile-ios CODE_SIGNING_ALLOWED=NO build
```

현재 Mac에서 서명 없는 iOS 기기용 빌드가 성공했다. 실기기 설치에는 Xcode에서 본인 Team과 고유 Bundle ID를 설정해야 한다. 현재 ID `com.ajc.shottracer.dev`는 개발용이며 스토어 등록에 사용 확정한 ID가 아니다. CoreSimulator 서비스 버전 불일치로 시뮬레이터 실행은 검증하지 못했다.

Android는 JDK 17, Android SDK 플랫폼 35·Build Tools 35.0.0·NDK 27.0.12077973·CMake 3.22.1로 구성한다. Gradle 8.11.1 wrapper와 배포 ZIP SHA-256 검증값을 포함한다. 개발 빌드의 compile/target SDK 35는 스토어 제출 적합성을 의미하지 않으며 출시 시 갱신한다.

```bash
cd mobile-port/app/android
./gradlew :app:assembleDebug
```

현재 Mac에서 arm64-v8a·x86_64 네이티브 코어를 포함한 디버그 APK 빌드와 `lintDebug`가 성공했다. Android 14 에뮬레이터 설치와 편집기·라이브 카메라 기본 동작을 검증했으며 실기기 검증은 남아 있다.

Android Studio에서 이 폴더를 열거나 `ANDROID_HOME`을 준비한 SDK 경로로 지정한다. SDK 경로를 Git에 저장하지 않는다. 생성 APK는 `app/build/outputs/apk/debug/`에 있으며 커밋하지 않는다.

### 편집기 테스트 방법

1. 새 APK를 설치하거나 Xcode에서 iPhone 앱을 다시 빌드·설치한다. 가져오기 아이콘으로 로컬 영상을 연다. iPhone은 Photos 선택도 가능하다.
2. 앞뒤 프레임 아이콘이나 슬라이더로 이동한다. **시작점 지정**을 누르고 타격 직전 공을 선택하면 체크 표시가 생긴다. **분석(Analyze)** 을 누르면 자동 추적하고, **착지점** 도구로 도착 위치를 누르면 분석 없이 수동 궤적을 그린다. 옆의 **리셋**은 확인 후 현재 프로젝트의 편집·분석을 초기화하고 첫 프레임으로 돌아간다. 영상 사본은 유지하며 실행 취소로 편집을 복원할 수 있다.
3. **+**로 샷을 추가한다(최대 4개). 샷 탭을 선택한 뒤 녹색 착지 핸들과 하늘색 정점 핸들을 드래그한다. 착지 프레임 도구는 표시 프레임을 착지 시각으로 설정한 후 착지점 선택으로 전환한다.
4. 설정에서 비행·정점 시간, 속도, 스타일, 팝업, 로고와 슬로모션을 조절한다. 원·선은 두 점을 누르고 수동 스윙 포인트는 프레임마다 지정한다. 핀치로 확대하고 이동 도구로 옮기며 두 번 눌러 화면에 맞춘다.
5. 내보내기 후 리뷰 아이콘으로 앱 안에서 완성 MP4를 재생한다. 리뷰는 궤적 속도·편집 재생과 독립적으로 미디어 재생 속도 1배로 열린다. 완성 MP4에 이미 적용된 슬로모션은 해당 영상의 일부로 유지된다. 완성 영상은 사진 앨범에 자동 저장하며 실패 시 저장 아이콘으로 다시 시도한다. iPhone은 첫 저장 시 사진 추가 전용 권한을 요청하고 Android는 Movies/ShotTracer에 저장한다. iPhone 리뷰 화면에서 공유도 가능하다. 프로젝트 아이콘에서 저장된 편집을 다시 열 수 있다. 일괄 내보내기는 저장 프로젝트를 순서대로 처리한다. 프로젝트 목록에서 Android는 **프로젝트 삭제…**, iPhone은 항목 선택 또는 한 항목 밀기로 삭제를 시작한다. 개별·전체 선택 후 확인하면 앱 내부 프로젝트 사본·편집 정보·그 프로젝트 출력본만 삭제한다. Photos·파일 앱 원본과 별도로 저장한 출력본은 유지한다. 프로젝트 삭제는 실행 취소할 수 없다.

Android 14 에뮬레이터에서 미커밋 합성 640×360/30fps/90프레임 영상으로 확인했다. 1→2프레임 이동 시 0.000→0.033초로 바뀌고, 착지 드래그가 정규화 좌표로 저장되며, 샷 추가 후 실행 취소가 1샷으로 복원됐다. 정상 출력은 궤적·팝업·원·워터마크를 포함한 3초/90프레임 H.264 MP4였고 앱 리뷰 화면에서 열렸다. 확대 화면의 복귀 버튼을 확인했고, 2배 구간 슬로모션은 4.6초/138프레임 H.264 무음 파일을 생성했다. 실제 골프 추적 정확도나 iPhone 실행 검증을 의미하지 않는다. 추가 프로젝트 조작 검증에서 시작점 체크·분석 활성화, 합성 관측점 70개, 리셋 후 영상 유지, 삭제 취소 후 테스트 프로젝트 2개 유지, 전체 선택 삭제 후 두 앱 내부 테스트 폴더 삭제와 현재 편집기 초기화를 확인했다. Android JVM 테스트 18개는 YUV 변환·회전 및 겹치는 슬로모션 구간의 시간 변환, 관측을 보존하는 퍼트 착지 보정과 타임라인의 가변 프레임률·예상/영상 밖 이벤트와 자동 관측을 보존하는 드래그 시간 제약을 확인한다. Android 에뮬레이터에서 시작 1프레임(0.000초)→착지 31프레임(1.000초)→시작 1프레임 이동과 미리보기의 두 위치 이름을 확인했다.

### 남은 작업과 실제 사용 제한

**데스크톱 전체 기능 이식이나 스토어 출시 완료 상태는 아니다.** 데스크톱 프로젝트 가져오기와 모바일 비밀번호 해제는 아직 이식 전이다. 인물 마스크와 자동 손목·클럽 경로는 네이티브 추론으로 구현했고 수동 스윙 포인트도 유지한다. 비행 공 검출·작은 평행 이동 보정은 데스크톱 LK/RANSAC과 동등하지 않으며 네이티브 포즈 백엔드의 마스크·관절 결과가 데스크톱과 동일하다고 보장하지 않는다. 수동 경로는 자유 곡선 그리기 대신 시작·정점·착지 곡선이다.

실제 골프 영상과 Android/iPhone 실기기에서 추적 정확도, 코덱·오디오, HDR, 회전, 가변 프레임률, 발열·메모리를 검증해야 한다. 프레임 조작은 원본 타임스탬프 표를 사용한다(Android 인덱스 디코드/iPhone 정확한 시각 디코드). 분석은 최대 변 640px·최대 30fps로 표본 추출하며 조작에는 모든 원본 프레임을 사용한다. 정상 출력은 플랫폼 인코더로 원본 크기를 유지하지만 오버레이는 분석 해상도에서 합성하며 HDR 보존 파이프라인은 아니다. Android 슬로모션 개발 출력은 분석 크기·30fps·무음이다. iPhone은 최고 품질 프리셋과 무음 리타이밍 composition을 사용한다.

긴 분석·출력 중에는 앱을 열어둔다. 백그라운드 작업과 OS 종료 후 미완료 작업 복구는 남아 있으며 완료된 편집 저장은 다시 열 수 있다. 캐시 정리, 더 세밀한 도형·팝업 편집, 접근성과 기종별 검증도 필요하다. 라이브 녹화는 이미 궤적이 합성된 영상으로 재편집 가능한 추적 프로젝트가 아니다. App Store·Play 공개 출시에는 서명한 기기 검증과 스토어 준비가 필요하다.


### 영상 위 팝업 정보 카드

편집기에서 새로 만드는 카드는 **화면 왼쪽 위**·샷 시작 시각을 기본으로 사용하며 기존 저장 위치·시각은 유지한다. **저장 및 미리보기**를 누르면 실제 표시 가능한 원본 프레임으로 이동한다. Android는 설정 → 팝업 추가에서 기존 카드 편집·삭제 또는 새 팝업을 선택한다. iPhone은 설정 → 팝업의 미리보기/편집과 수정 저장을 사용한다. 설정한 구간에 영상 프레임이 없으면 위치·지연·표시 시간을 고치도록 경고를 유지해 아무것도 표시되지 않는 이유를 알 수 있게 했다.

‘샷 종료 후 숨기기’는 지연 시간이 길어도 표시 시작 후 최소 1초 유지한다. 이전에는 고정 종료 시각이 시작보다 빨라지면 카드가 영원히 표시되지 않았다. 짧은 영상에서 착지 위치의 표시 시각이 영상 뒤에 있는 경우도 경고하며 임의로 시각을 바꾸지 않는다. 지정 시간/영상 끝까지 표시 및 기존 프로젝트 설정은 유지한다. 제목·값을 두 줄로 구분하고 같은 위치의 카드를 쌓아 속도 카드가 거리 카드를 덮지 않도록 했다. 미리보기·MP4 출력은 같은 시간·배치 함수를 사용한다.

회귀 테스트는 긴 지연, 지정 시간/영상 끝, 가변 프레임률의 첫 표시 프레임, 영상 밖 구간, 카드 겹침·경계 배치를 확인한다. Android 14 에뮬레이터에서 한글 거리·속도 카드와 2초 지연 착지 카드가 3.200초 미리보기와 6초/180프레임 H.264 출력에 함께 표시됐다. 실제 추가 창에서 저장한 새 카드는 왼쪽 위 기본값을 보관하고 0.300초의 10프레임으로 이동했다. iPhone 빌드는 통과했으나 실행 동작은 실기기 검증이 필요하다.

### 타임라인 시간 드래그와 사진 앨범 저장

노란 시작 공·초록 착지 깃발을 가로로 드래그하면 실제 원본 프레임에 맞춰 시간이 바뀌며 가변 프레임률 영상도 지원한다. 시작을 옮겨도 절대 착지 시각과 랜딩 위치는 유지하고, 착지를 옮겨도 시작 시각과 랜딩 위치는 유지한다. 비행 구간은 0.2–15초 및 사용 가능한 원본 프레임 범위로 제한해 두 마커가 교차하지 않는다. 영상 밖의 예상 착지도 보이는 타임라인 안으로 끌어올 수 있다. 자동 관측·`baseModel`은 변경하지 않으며 마스크·손목·클럽 관측은 실제 원본 프레임 기준을 유지한다. 재분석하지 않는다. 드래그 한 번은 실행 취소 한 번으로 되돌리고 제스처 취소 시 원래 편집 상태로 복원한다. 프로젝트 JSON은 이동 중 매번 저장하지 않고 손을 놓을 때 저장한다. iPhone VoiceOver로는 이벤트를 한 프레임씩 조절할 수 있다.

정상·슬로모션 내보내기와 라이브 촬영 완료 후 사진 앨범에 자동 저장을 시도한다. Android는 전체 갤러리 권한 없이 **Movies/ShotTracer**에 완료된 MediaStore 영상을 공개하고, 같은 출력 재저장 시 기존 소유 항목을 확인해 중복 삽입을 막는다. iPhone은 번역된 `NSPhotoLibraryAddUsageDescription`과 Photos **추가 전용** 권한을 사용한다. 기존 사진 읽기 권한이나 더 넓은 권한이 필요한 전용 앨범 생성을 요청하지 않는다. 성공한 출력 URL을 기억해 자동 중복 추가를 방지한다. 권한 거부·저장 실패 시 앱 안의 완성 영상은 유지하고 재시도 안내를 표시한다. iOS 설정에서 사진 추가를 허용한 뒤 저장 아이콘으로 다시 시도할 수 있다. 갤러리·Photos 사본은 프로젝트 폴더와 별개이므로 프로젝트를 삭제해도 남는다. [Android MediaStore 안내](https://developer.android.com/training/data-storage/shared/media), [Apple Photos 영상 추가](https://developer.apple.com/documentation/photos/phassetchangerequest/creationrequestforassetfromvideo(atfileurl:)).

Android 14 에뮬레이터에서 시작 0.000→0.300초 드래그 후 착지 1.000초·위치 유지, 착지 0.666666초 드래그 후 시작 0.300초 유지를 확인했다. 실행 취소 한 번으로 착지 드래그 전체가 복원됐다. 첫·마지막 마커와 Android 뒤로 가기 제스처가 충돌하지 않도록 마커 영역만 제외했다. 편집 결과 1.2초 영상과 가상 카메라 2.321초 영상이 Movies/ShotTracer에 `IS_PENDING=0`·정상 크기·재생시간으로 등록됐고, 같은 출력 재저장 시 항목이 늘지 않았다. 카메라 화면을 닫는 경우에도 캡처 마무리 과정에서 앨범 저장을 수행한다. iPhone 기기용 빌드와 생성된 Photos 사용 설명 키는 확인했으나 실제 권한·저장/거부·제스처 동작은 실기기 검증이 필요하다.

### 기기 내 인물·스윙·퍼트 자동 분석

**비행 샷** 또는 **퍼트**를 선택하고 시작 공을 지정한 뒤 **분석**을 누른다. 가져온 영상의 선택 프레임 이전 최대 1.2초부터 이후 최대 15초까지 영상 범위 안에서 분석한다. 공 추적은 최대 30fps, 인물은 선택 프레임 부근 30fps·나머지 최대 15fps로 표본 추출한다. 샷별로 자동 공 관측·기본 모델, 카메라 이동, 자동 손목·클럽 관측, 시각별 작은 알파 마스크 PNG를 앱 내부 분석 폴더에 저장한다.

- **Android:** MediaPipe Tasks Vision 1.1.1·CPU·전체 포즈 1명·분할 활성화. Gradle `preparePoseModel`이 공식 고정 버전 `pose_landmarker_full/float16/1` 모델을 포함하며 SHA-256은 `5134a3aad27a58b93da0088d431f366da362b44e3ccfbe3462b3827a839011b1`이다. 처음 개발 빌드할 때 의존성·모델 다운로드가 필요하지만 설치 앱은 INTERNET 권한이나 모델 다운로드 없이 동작한다. 모델은 `app/build/`에 생성하고 커밋하지 않는다. SDK `MPImage`가 입력 비트맵을 소유하므로 별도 복사본을 전달한다. [Google 포즈 가이드](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/android)
- **iPhone:** Apple Vision `VNGeneratePersonSegmentationRequest`와 `VNDetectHumanBodyPoseRequest`를 사용한다. 회전 보정 프레임을 입력하고 관절의 아래쪽 원점을 영상의 위쪽 원점으로 변환한다. 앱이 추가 모델 다운로드나 계정을 요구하지 않는다. 양쪽 손목이 신뢰도 기준을 통과해야 중점을 손 경로로 사용한다. 어깨·발목 간격으로 클럽 검색 반경을 추정한다. [Apple 인물 분할](https://developer.apple.com/documentation/vision/vngeneratepersonsegmentationrequest), [Apple 자세 분석](https://developer.apple.com/documentation/vision/vndetecthumanbodyposerequest)
- **클럽 헤드:** 공통 C++ 검출기가 카메라 이동을 정렬한 회색조 3프레임에서 확장한 인물 마스크를 제외하고, 손목 가까이 연결된 움직임 중 신장 기반 반경 내 가장 먼 점을 찾는다. 자동 스윙은 검출 타격 시각 전후 1.2초 관측을 보관한다. 손목은 청록색, 클럽은 금색이다. 검출 실패·낮은 신뢰도 구간은 비워두며 0.18초 넘는 공백은 선을 연결하지 않는다. 추측한 클럽 점으로 대체하지 않는다.
- **인물 가림:** 설정에서 **인물 뒤로 궤적 표시**를 켜고 자동 스윙은 손목/클럽/둘 다/끄기를 선택한다. 미리보기·출력의 같은 렌더러가 시각별 마스크 위치에서 궤적·스윙 알파를 제거한다. 팝업·도형·로고·워터마크는 계속 표시한다. 마스크 파일은 폭 최대 256px이며 메모리 캐시는 작게 제한한다. 요청 시각에서 0.11초 넘게 떨어진 마스크는 재사용하지 않는다. 표시 설정 변경은 재분석하지 않는다.
- **퍼트:** 정규화 상관 템플릿 매칭에 속도 예측, 카메라 이동 보정, 신뢰도 기준, 느린 템플릿 갱신을 적용한다. 비행 검출 밝기 기준보다 어두운 공도 추적하며 소실·정지 후 종료한다. 탄도 곡선을 만들지 않고 관측 지면 경로를 그린다. 시간·속도·착지 보정은 자동 관측을 보존하면서 지면 경로의 시간·끝부분을 조절하고 퍼트에서는 정점 도구를 끈다. 모드 변경 시 공 분석 결과를 초기화하므로 다시 분석한다.

공 또는 인물 분석 실패 시 UI에 관측 수와 실패 내용을 표시하고 독립적으로 성공한 결과는 보관한다. 자동 관측은 수동 편집과 별도다. 재분석의 이전 마스크 폴더는 실행 취소 호환을 위해 남기며 프로젝트 삭제 시 함께 제거한다. 실제 검출 품질은 가림·모션 블러·자세·배경 대비·카메라 이동에 영향을 받는다. 가져온 영상의 자동 분석과 기존 실시간 촬영은 구분된다. 라이브 촬영은 계속 관측 공 경로를 표시하며 촬영 중 이 무거운 인물·클럽 분석을 실행하지 않는다.

Android 14 에뮬레이터에서 공식 MediaPipe 예제 인물 이미지와 어두운 합성 퍼트 공으로 마스크 36장·손목 관측 36개·공 관측 28개를 확인했다. 움직이는 클럽이 없는 영상에서는 클럽 0개였다. 공통 코어의 합성 샤프트 테스트는 헤드를 검출하고 인물·연결되지 않은 움직임·정지 물체를 제외했다. 인물 몸통을 지나는 수동 궤적을 가림 켜기/끄기로 출력하자 선택 영역의 빨간 궤적 픽셀이 0개/257개였다. 같은 원본 시각 0.900초의 앱 미리보기에서도 해당 영역의 빨간 궤적 픽셀이 0개였다. 실행 연결·합성 검증이며 실제 골프 정확도 검증은 아니다. iPhone 빌드는 통과했으나 Vision 추론·마스크 정렬은 실기기 검증이 필요하다.

### iPhone 라이브 카메라 촬영

Xcode에서 앱을 다시 설치한 뒤 **카메라로 라이브 샷 촬영**을 누른다. 카메라 접근을 허용하고, 소리를 포함하려면 마이크 접근도 허용한다. 사진 보관함 전체 접근 권한은 요구하지 않는다.

1. 휴대폰을 세로로 고정하고 공이 선명하게 보이도록 구도를 맞춘다.
2. 카메라 화면에서 시작 공을 누른다.
3. **촬영 및 추적 시작**을 누른 후 샷을 친다. 관측한 경로가 실시간으로 표시된다.
4. **촬영 중지 및 저장**을 누르거나 최대 15초까지 기다린다.
5. 완료 영상은 Photos에 자동 추가한다. 첫 저장 시 사진 추가 권한을 허용하고 실패하면 **사진 앨범에 저장**으로 다시 시도한다. 완성본 리뷰에서 공유도 가능하다. 앱 내부 원본은 Files 공유 디렉터리의 `captures/`에 보관되며 자동 클라우드 백업에서 제외된다.

iPhone 카메라는 AVFoundation 기반이며 Android의 별도 Camera2 구현은 아래에 설명한다. 실시간 처리를 위해 VGA(세로 480×640)·최대 30fps를 사용하며, 처리 지연 시 프레임이 생략될 수 있다. 궤적은 기존 `TrackingSession`/`st_render`로 합성해 저장한다. 노란 공 선택 표시는 조작용이므로 녹화에 포함하지 않는다. 추적에 실패해도 영상은 저장하고 실패 사실을 표시한다. 마이크 권한이 없으면 무음으로 촬영하며 화면에 알린다.

앱이 백그라운드로 이동하거나 카메라 사용이 중단되면 촬영을 마무리한다. 새 촬영 시 공을 다시 지정한다. 저장된 라이브 영상에는 이미 궤적이 합성되어 있으며 기존 편집기의 경로를 다시 편집하는 프로젝트 형식은 아니다. 기존 영상 가져오기·편집 경로도 유지한다. 실기기 카메라, 마이크 동기화, 실시간 처리 속도와 실제 골프 샷 추적 정확도는 아직 검증 전이다.


### Android 라이브 카메라 촬영

새 APK를 설치하고 **카메라로 라이브 샷 촬영**을 누른다. 카메라 접근을 허용한다. 마이크는 선택 사항이며 거부하거나 기기가 마이크를 사용할 수 없으면 무음으로 촬영하고 화면에 알린다. 영상 가져오기만 사용할 때는 카메라 권한을 요구하지 않는다.

1. 휴대폰을 세로로 고정한 뒤 화면에서 시작 공을 누른다.
2. **촬영 및 추적 시작**을 누른 후 샷을 친다. 관측한 공 경로가 화면에 표시된다.
3. **촬영 중지 및 저장**을 누르거나 최대 15초까지 기다린다.
4. 완료 영상은 갤러리의 **ShotTracer**에 자동 추가한다. 실패하면 **사진 앨범에 저장**으로 다시 시도한다.

Camera2의 YUV_420_888 프레임을 각 plane의 행·픽셀 간격에 맞게 읽고 센서 방향을 보정한다. 최대 변 640px, 최대 30fps를 요청하며 실제 해상도와 속도는 카메라 지원 범위에 따른다. 미리보기에는 공통 `TrackingSession`의 궤적·워터마크를 합성하고, 바로 그 비트맵을 EGL/MediaCodec 인코더에 전달한다. 노란 선택 표시는 녹화에서 제외한다. 늦은 카메라 프레임과 UI 업데이트는 쌓아두지 않으며 처리 지연 시 프레임이 생략될 수 있다.

마이크가 사용 가능하면 PCM을 AAC로 인코딩하여 H.264 영상과 MP4로 묶는다. 코덱 형식이 준비될 때까지의 패킷 보관량과 종료 대기 시간을 제한한다. 카메라가 실시간 센서 시계를 제공하지 않으면 영상 도착 시각을 기준으로 오디오 시작 시각을 추정하므로 실기기 동기화 확인이 필요하다.

앱이 백그라운드로 이동하거나 화면을 나가면 카메라를 닫고 진행 중인 영상을 마무리한다. 임시 `.partial.mp4`는 성공한 경우에만 완성 파일명으로 바꾼다. 완료 영상은 앱 전용 `files/captures/`에 보관되며, 라이브 화면을 다시 열면 가장 최근 완료 영상을 저장할 수 있다. 추적이 실패해도 촬영 영상은 워터마크와 함께 저장하고 추적 실패를 알린다. 앱의 자동 백업에서는 촬영 영상을 제외한다.

검증 명령은 `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`다. 추가 JVM 테스트 4개는 YUV 행 패딩·색차 plane 픽셀 간격·crop·센서 회전·색상 범위를 확인한다. 실제 골프 영상 정확도, 기종별 카메라·코덱 지원, 오디오 동기화와 지속 처리 속도는 실기기 검증 전이다. 라이브 결과는 궤적이 합성된 영상이며 재편집 가능한 프로젝트 형식은 아니다.


Android 14 에뮬레이터의 가상 카메라로 15초 자동 종료, H.264 480×640 + AAC MP4 생성, 무음 수동 중지, Downloads 저장, 백그라운드 이동 시 약 2초 영상 마무리와 카메라 해제를 확인했다. 실제 카메라·마이크 입력과 골프 샷 정확도는 아직 실기기 검증 전이다.

### 대표 이미지, 분석 방식 선택과 움직임 근거

사용자가 제공한 `assets/brand/shottracer-user-logo.jpg` 원본을 그대로 보관한다. 중앙 정사각형 크롭을 Android 런처·상단과 iPhone 앱 아이콘·상단·빈 편집 화면에 적용했다. 기존 생성 로고는 미사용 대안으로 보관한다. 완성 영상에 이 이미지를 자동 삽입하지 않는다.

가져온 영상을 임팩트 직전에 멈추고 **시작점 지정**을 선택한 뒤 공을 누르면 위치와 시각만 저장한다. 분석은 자동 실행하지 않는다. 이후 양쪽 앱에서 두 가지 중 선택한다. **분석(Analyze)** 을 누르면 오프라인 공·인물·클럽 추적 후 예측 궤적을 생성하고, **착지점** 도구로 도착 위치를 누르면 분석 없이 수동 궤적을 그린다. 프레임을 앞으로 이동하면 자라나는 선을 확인할 수 있고, 착지 시각은 타임라인에서, 정점은 핸들로 조정한다. 자동 분석에서 보이지 않는 착지는 예측이며 위치를 직접 보정할 수 있다. 라이브 카메라는 공 선택 후 촬영 시작을 눌러야 한다.

설정의 **영상에서 관측한 움직임**에서 최초 관측 최대 2초간 공의 이동량·화면상 중앙 속도, 최대 0.25초 구간의 초반 화면 방향, 임팩트 부근 클럽의 화면상 중앙 속도를 확인한다. 원본 타임스탬프·카메라 보정 관측값과 분석 해상도의 픽셀 단위를 사용한다. 예측 궤적·수정한 타이밍/핸들·임의 스매시 팩터를 사용하지 않는다. 관측 3개 미만, 역순/중복 시각, 0.125초 초과 간격, 너무 짧은 구간이면 해당 결과를 표시하지 않는다. 30fps에서는 클럽이 흐리거나 누락될 수 있으며 런치모니터 측정이 아니다.

**이 화면상 통계로 실제 비거리(m)를 계산하는 기능은 구현하지 않았다.** 카메라 자세·길이 보정과 공의 발사 조건이 필요하며 클럽 움직임만으로 실제 볼 속도·스핀·비거리를 알아낼 수 없다. 관련 평면의 실제 기준 길이와 적절한 측면 영상은 향후 보정된 투영 추정에 도움이 되지만 원근 깊이나 스핀까지 자동 해결하지 않는다. 사용자는 보정 자료가 없으며 이번에는 자동 궤적과 영상 속 속도 표시를 우선하도록 확인했다. 확인되지 않은 물리 가정을 적용하지 않는다. 초반 비행에는 볼 속도·발사각/방향·스핀이 관여한다([Titleist 발사 조건](https://www.titleist.com/learning-lab/performance/golf-shot-launch-conditions)). 클럽 속도·볼 속도·캐리는 서로 다른 값이다([Trackman 정의](https://support.trackmangolf.com/hc/en-us/articles/5089892383515-Practice-Trackman-Data-Parameter-Definitions)). 기존 거리·속도 팝업 값은 계속 수동 입력이다.

이번 변경 검증: Python/공통 코어 테스트 76개, Android 디버그 빌드·JVM 테스트·린트, iPhone 기기 SDK 무서명 빌드. 실제 휴대폰 정확도와 촬영 검증은 남아 있다.

Android 14 에뮬레이터 동작 검증: 시작점 선택만으로 좌표가 저장됐고 관측점은 0개, 자동 모델은 없었다. 이어 착지점 지정 시에도 관측점 0개인 상태에서 수동 끝점이 저장됐다. 같은 합성 60프레임 영상의 초기 사본에서 시작점 선택 후 Analyze를 누르자 관측점 55개와 16값 자동 모델이 생성됐다. Python/공통 코어 테스트 76개, Android 빌드·JVM 테스트·린트와 iPhone 무서명 빌드를 통과했다. 실제 휴대폰 추적 정확도 검증은 남아 있다.
